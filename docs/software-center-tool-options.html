⚠️ Why MDM isn't automatically "out of the question"
Apple's own MDM-side fees are close to $0/year (see the Cost tab) — the real blocker was never money, it's the setup effort: a D-U-N-S number, Apple's identity verification, and an annual certificate renewal that breaks all device management if missed. Worth knowing before ruling it out entirely.

✅ What favors staying custom
The catalog/approve/download/audit loop already passes real tests, per this repo's README. Munki would not add anything to that half — its real edge is the self-update loop and its huge install base.
⚠️ What favors Munki
Community support, a documented root-LaunchDaemon pattern for privileged install (the exact gap this repo's helper still has), and a ready client UI (Managed Software Center) if the custom SwiftUI app's install UX needs less maintenance long-term.
Practical middle path
Borrow Munki's root-LaunchDaemon install pattern to finish this repo's privileged-install helper, and add a background check-in timer to the client — keep the already-tested admin console and Santa wiring as-is, instead of a full swap.

⚠️ The honest trade-off, without MDM
Without MDM, the strongest design (on-device filter agent) drops to weakest, because its edge was MDM-enforced non-removability. AdGuard Home becomes the practical pick — accept that a technical employee can bypass it by changing DNS settings by hand, and treat that as a known, accepted gap rather than something solved today.
DELIVERY LAYER — MDM, STILL OPEN

Zero-touch enrollment for new Macs, non-removable enforcement (an employee with admin rights can't just uninstall Santa or the filter agent), fleet-wide push of config/policy changes, and Mac App Store restriction — the one control point Munki and Santa cannot touch at all.

⚠️ What none of these give you for free
Whichever MDM option is picked (including Apple's own), the catalog server (or Munki), Santa's sync server, and AdGuard Home/Pi-hole still need to be built and hosted separately — MDM only handles enrollment, profile push, non-removability, and App Store restriction, not app cataloging or binary blocking.
COST — EVERY PATH, SIDE BY SIDE
Apple's own MDM-side fee is nearly flat, regardless of which path is picked
Apple Developer Program: $99/year, one account for the whole company, needed for code signing/notarization either way. Apple Business enrollment and the APNs push certificate are both free. What actually swings the total is hosting — and whether installer files get stored on our own server at all.
